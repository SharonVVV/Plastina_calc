# Документация Задачи №4 — Симулятор лабораторного стенда

> **Задача №4.** Виртуальная копия экспериментальной установки Керимова.
> Пластина с тыльной стороны нагревается силиконовыми матами; в металл
> вдоль высоты заделаны **20 термопар**. Пользователь задаёт мощность,
> нажимает «Включить» — стенд прогревается до установившегося режима
> с плавной анимацией. Показания термопар, температурное поле пластины
> и расчётные характеристики выводятся в реальном масштабе.

В отличие от Задач №2 и №3, здесь **нет нового физико-математического
расчёта** — используется тот же солвер `task2_solver.solve_task2`, что и
в Задаче №2 (без изоляции). Вся ценность модуля — в **UX-обвязке**:
двухпанельная визуализация, анимация прогрева/остывания, выборка значений
T в конкретных точках термопар, и набор инженерных таблиц.

Документ описывает один новый файл — `pages/4_Задача_4_Симуляция.py` —
и относительно небольшие изменения в `app.py` и `CLAUDE.md`.

## 1. Постановка задачи

### 1.1. Что моделируем

| Что | Значение по умолчанию |
|---|---|
| Геометрия пластины (b × L × δ) | 100 × 2000 × 12 мм (как в Task 2) |
| Материал | Д16-Т (λ = 130 Вт/(м·К)), ε = 0,05 |
| Среда | воздух 20 °C, 101 325 Па |
| Методика конвекции | Керимов 1992 (можно выбрать любую из 8) |
| Мощность нагревателей | 480 Вт (слайдер 0…1500 Вт) |
| Учитывать λ_м·d²T/dz² | да (тумблер как в Task 2) |

### 1.2. Координаты 20 термопар по высоте

Сгущены к нижней кромке — там пограничный слой самый тонкий, локальный
α максимален, и градиенты температуры по высоте наиболее интересны.
Координаты (z от днища, в мм) **жёстко вшиты** в исходник
(`THERMOCOUPLE_Z_MM`):

```
50,  65,  80,  95, 110, 130, 160, 195, 235, 285,
345, 415, 505, 615, 745, 900, 1095, 1325, 1610, 1950
```

Шаг по высоте растёт примерно геометрически: первые 10 термопар — в
нижней пятой части плиты, остальные 10 — равномернее по оставшимся
85 % высоты.

### 1.3. Сценарии пользователя

1. **Холодный старт.** Страница открыта, стенд выключен. Тепловая карта
   пластины целиком в цвете T_∞, маркеры термопар тёмные, таблица
   показаний — все 20 °C.
2. **Включить стенд.** Кнопка «Включить» → запускается анимация прогрева
   ~5 секунд → установившийся режим. Колорбар цветовой шкалы переключается
   с широкой на узкую.
3. **Изменить мощность / параметры.** При любом изменении (слайдер
   мощности, методика, материал, ε, и т.п.) солвер пересчитывает результат
   и страница обновляется без анимации (показывается сразу финальное
   состояние).
4. **Выключить стенд.** Кнопка «Выключить» → обратная анимация остывания
   ~5 сек → плита холодная.

## 2. Архитектура страницы

Один файл — `pages/4_Задача_4_Симуляция.py`, ≈ 920 строк (включая
комментарии и CSS). Логически делится на блоки:

```
1. Imports + INFERNO_SCALE (workaround Plotly-бага, см. §6).
2. Constants: THERMOCOUPLE_Z_MM, ANIMATION_FRAMES, ANIMATION_DURATION_S.
3. CSS (IBM Plex, классы .t4-*).
4. Header (заголовок + лид).
5. Session-state defaults: t4_power_on, t4_animate, t4_anim_direction.
6. Expander «Параметры стенда» (свёрнут по умолчанию).
7. Слайдер мощности + кнопки on/off + статус-чип.
8. Кэшированный солвер _solve_steady() → result.
9. Vis: _compute_visualization_arrays() + _build_figure() → fig.
10. Рендер фигуры (с анимацией или без).
11. Caption + информационный бейдж t_воздуха.
12. Таблица показаний термопар (HTML, 3 колонки).
13. Раздел «Анализ свободно-конвективного теплообмена» —
    4 expander'а (T(z), α/Ra, режимы, числа подобия).
```

### 2.1. Параметры стенда (expander)

Все настройки стенда сосредоточены в одном свёрнутом блоке, чтобы
основной экран был чистый — слайдер мощности и кнопки. Поля:

- **Геометрия**: b, L, δ (мм)
- **Материал и излучение**: материал из `MATERIALS`, λ_металла (Вт/(м·К)),
  ε поверхности
- **Среда и методика**: t_воздуха (°C), P (Па), методика конвекции —
  selectbox из 8 UHF-корреляций (`ORDER`)
- **Тумблер** `axial_conduction` — учитывать ли продольную
  теплопроводность в металле (по умолчанию ON)
- **Информационная строка**: координаты 20 термопар в monospace

### 2.2. Управление мощностью

```python
N_setpoint = st.slider(...)         # 0…1500 Вт
btn_on  = st.button('Включить стенд', disabled=(N_setpoint <= 0))
btn_off = st.button('Выключить',      disabled=not ss.t4_power_on)
```

Обработка кнопок — после отрисовки виджетов, чтобы прочитать актуальные
значения слайдеров:

```python
if btn_on and N_setpoint > 0:
    ss.t4_power_on = True
    ss.t4_animate = True
    ss.t4_anim_direction = 'on'
    st.rerun()

if btn_off:
    ss.t4_power_on = False
    ss.t4_animate = True
    ss.t4_anim_direction = 'off'
    st.rerun()
```

Флаг `t4_animate` — одноразовый: после следующего рендера он сбрасывается
в False. Это гарантирует, что анимация проигрывается ровно один раз
после нажатия кнопки, а не повторно при каждом rerun.

### 2.3. Расчёт установившегося режима

```python
@st.cache_data(show_spinner=False)
def _solve_steady(key, N_total_W, b_mm, L_mm, delta_mm, lambda_metal,
                  material_name, t_fluid_C, P_Pa, eps_surface,
                  axial_conduction):
    return solve_task2(
        key=key, N_total_W=max(N_total_W, 1e-6),
        b_mm=b_mm, L_mm=L_mm, delta_mm=delta_mm,
        lambda_metal=lambda_metal, material_name=material_name,
        t_fluid_C=t_fluid_C, P_Pa=P_Pa, eps_surface=eps_surface,
        N_nodes=N_NODES_SOLVER, x_min_mm=X_MIN_MM,
        axial_conduction=axial_conduction,
    )
```

Кэш-ключ — кортеж всех аргументов. **Любой новый параметр должен быть
добавлен в сигнатуру `_solve_steady`** (иначе будет stale-кэш). Сейчас
`axial_conduction` в ключе — это критично, иначе тумблер не даст эффекта.

Если стенд выключен или мощность нулевая — солвер не вызывается, и
`result = None`.

### 3.2. Адаптивная цветовая шкала

Внутренний градиент плиты (~16 K на 180 K) почти не виден в широкой
шкале [T_∞, T_max]. Поэтому шкала переключается в зависимости от
состояния:

| Состояние | zmin … zmax | Что видно |
|---|---|---|
| Стенд выключен | [T_∞, T_∞+1] | Плита однородно холодная |
| Анимация прогрева | [T_∞, T_max_ss] | Заливка снизу-вверх, динамика |
| Статика, стенд работает | [T_min_ss − ε, T_max_ss + ε] | Внутренний градиент плиты |

Реализация — параметр `narrow_scale: bool` в `_build_figure()`:

```python
T_min_plate = state.get('T_min_overall', t_fluid_C)
if narrow_scale and (T_max - T_min_plate) > 0.5:
    margin = max(0.3, 0.05 * (T_max - T_min_plate))
    zmin = T_min_plate - margin
    zmax = T_max + margin
else:
    zmin = t_fluid_C
    zmax = max(T_max, t_fluid_C + 1.0)
```

После окончания анимации прогрева отрисовывается дополнительный финальный
кадр уже с `narrow_scale=True` — переключение шкалы выглядит как «всё
проявляется».

## 4. Анимация прогрева

### 4.1. Общая идея

Streamlit не имеет встроенной анимации `plotly_chart`; нативные Plotly
frames неудобны для авто-запуска. Используется простой подход на
`st.empty()` + `time.sleep`:

```python
ANIMATION_FRAMES = 22
ANIMATION_DURATION_S = 5.0

chart_holder = st.empty()

if ss.t4_animate:
    ss.t4_animate = False                  # одноразовый триггер
    direction = ss.t4_anim_direction       # 'on' или 'off'
    dt = ANIMATION_DURATION_S / ANIMATION_FRAMES

    for i in range(ANIMATION_FRAMES + 1):
        u = i / ANIMATION_FRAMES
        f = 1.0 - np.exp(-4.0 * u)        # экспоненциальный выход
        if i == ANIMATION_FRAMES: f = 1.0
        if direction == 'off':  f = 1.0 - f

        fig = _build_figure(..., narrow_scale=False)
        chart_holder.plotly_chart(fig, ...)
        time.sleep(dt)

    # Финальный «снэп» в установившийся режим — узкая шкала.
    if direction == 'on':
        fig = _build_figure(..., narrow_scale=True)
        chart_holder.plotly_chart(fig, ...)
```

### 4.2. Профиль T(t)

Профиль выхода **не физический** (real-time прогрев металла — десятки
минут), он визуально-демонстрационный:

$$
T(z, t) = T_\infty + (T_\text{ss}(z) - T_\infty) \cdot
         \big[1 - \exp(-4 u)\big], \quad u = t / T_\text{total}
$$

Коэффициент 4 подобран так, что к концу анимации (u=1) фактор ≈ 0,98;
последний кадр насильно установлен в 1,0 для точного попадания в
установившийся режим.

### 4.3. Параметры по умолчанию

- 22 кадра за 5 секунд → ~225 мс на кадр.
- Каждый кадр — полная перестройка фигуры + `chart_holder.plotly_chart()`
  заменяет содержимое placeholder'а. Перерисовка плавная, но всё-таки
  заметна как «дискретные шаги» — не gpu-анимация.

## 6. Особенность: workaround Plotly 6.x `#ffabab`

При построении двух Heatmap'ов на одной фигуре с разными `zmin/zmax`,
но одинаковым `colorscale='Inferno'` (string-name), Plotly 6.x по
неизвестной причине **подменяет первый цвет** палитры с `#000004`
(почти-чёрный) на `#ffabab` (светло-розовый). Эффект: воздушные/холодные
зоны рендерятся ярко-розовым, что разрушает всю визуализацию.

Воспроизведение и диагностика:

```python
fig._fullData[0].colorscale       # → [[0, '#ffabab'], [0.111, '#1b0c41'], ...]
```

Передача colorscale как explicit-списка с тем же первым цветом всё
равно подменяется. Передача списка с **другим** первым цветом — НЕ
подменяется.

**Фикс:** в начале файла собираем `INFERNO_SCALE` из
`plotly.colors.sequential.Inferno`, а первый элемент явно заменяем на
`#0a0418` (визуально неотличимо от `#000004`, но баг не срабатывает):

```python
_INFERNO_RAW = pc.sequential.Inferno
INFERNO_SCALE = [
    [i / (len(_INFERNO_RAW) - 1), c] for i, c in enumerate(_INFERNO_RAW)
]
INFERNO_SCALE[0] = [0.0, '#0a0418']
```

Все Heatmap/Scatter с цветовой заливкой на странице используют
`colorscale=INFERNO_SCALE`. Если когда-нибудь Plotly починят баг —
этот хак можно убрать и вернуться к `colorscale='Inferno'`.

## 7. Smoke-результаты на дефолтах

Запуск:
```bash
python3 -c "from task2_solver import solve_task2; \
  r = solve_task2(key='kerimov_1992', N_total_W=480, b_mm=100, L_mm=2000, \
                  delta_mm=12, lambda_metal=130, eps_surface=0.05, \
                  N_nodes=161, x_min_mm=10.0); \
  print(r.T_min_C, r.T_avg_C, r.T_max_C, r.residual_pct)"
```

Ожидаемый вывод:
```
186.3  192.2  201.9  -0.0001
```

Показания термопар на дефолтах (интерполяция расчётного профиля):
```
ТП 01 (z=50  мм):  195.5 °C
ТП 02 (z=65  мм):  196.0 °C
...
ТП 10 (z=285 мм):  201.8 °C  ← максимум
ТП 16 (z=900 мм):  186.3 °C  ← минимум
...
ТП 20 (z=1950 мм): 189.9 °C
```

Классическая «хампообразная» форма с пиком в районе lam→trans перехода
и подъёмом наверху из-за горячего верхнего торца — но при включённой
продольной теплопроводности профиль сглаживается, и амплитуда «хампа»
становится 16 K вместо 60-80 K как в Задаче №1.

При выключенном тумблере `axial_conduction` — амплитуда возрастает до
~100 K, шкала колорбара раздвигается до ≈ 140…250 °C.

## 8. Что можно расширить

- **Шум на термопарах.** Сейчас T_тп = идеальная интерполяция профиля.
  Можно добавить тумблер «эмулировать шум» с гауссовским σ ≈ 0,2 K.
- **Реалистичная динамика прогрева.** Текущая анимация — чисто визуальная
  (5 секунд для эффектности). Можно добавить вторую кнопку «реальное
  время» — рассчитать τ = m·c_p / (h·A) ≈ десятки минут и показать как
  идёт прогрев в ускоренном масштабе с засечками минут.
- **Хронометраж.** При анимации показывать текущее t, T_max(t).
- **Регуляторы.** PID-контроллер мощности по показаниям одной из
  термопар — целевая температура задаётся пользователем.
- **Экспорт.** Кнопка «выгрузить таблицу термопар в CSV» — пригодится
  студентам для оформления отчёта.
- **Координаты термопар.** Сейчас вшиты константой. Можно сделать
  редактируемым textarea или загрузку из CSV.
